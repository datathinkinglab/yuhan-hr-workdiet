## 19장 시연 — 가상 근태 파일 검사기

설계안 부록 A의 가상 CSV와 기대 결과로 실제 검사를 수행합니다. 모든 처리는 브라우저 안에서만 이뤄집니다.

| 행 | ID | 부서 | 기준 | 제출 | 기대 결과 |
|---:|---|---|---:|---:|---|
| 1 | H001 | A | 480 | 480 | 정상, 차이 0 |
| 2 | H002 | A | 480 | (빈칸) | 누락, 차이 공란 |
| 3 | H003 | B | 480 | 480 | 중복 ID, 차이 0 |
| 4 | H003 | B | 480 | 480 | 중복 ID, 차이 0 |
| 5 | H004 | C | 480 | 450 | 불일치, 차이 −30 |
| 6 | H005 | C | 480 | 오류 | 숫자 형식 오류, 차이 공란 |

**검사 규칙** — 같은 ID가 2행 이상이면 모두 중복 / 값이 비면 누락 / 숫자가 아니면 형식 오류 / 누락·형식 오류 행은 차이를 계산하지 않음 / 차이 = 제출 − 기준.

**진행 순서 (15분)**

1. **입력 확인 3분** — 오른쪽 기대 결과(고정)를 먼저 보여 주고 정답을 합의
2. **테스트 4분** — 클릭 또는 **검사 실행** → 결과 표와 주황 막대(실제)가 남색 막대(기대)와 일치하는지 대조
3. **규칙 변경 5분** — **허용 차이**를 `30분 미만 허용`으로 바꿔 H004 판정이 달라지는 것을 보여 주고, 기준은 사람이 정하는 업무 규칙임을 강조. CSV 상자에서 값을 직접 고쳐 다시 실행 가능
4. **요청문 검토 3분** — 검증된 예외(H004)만으로 만든 요청문 초안 확인. **요청문 프롬프트** 탭 → **검사 결과 넣기** → 복사해 AI에 입력. 담당자가 원본 값과 수신 범위를 확인한 뒤 발송

꼬이면 **초기화** 버튼으로 원래 CSV·기준·공개 전 상태로 돌아갑니다.

## 내용 수정 방법

**장 속성** — 각 `<section class="slide">`의 data 속성이 머리말·꼬리말·목차·노트를 자동 생성합니다.

| 속성 | 역할 | 예 |
|---|---|---|
| `data-no` | 하단 쪽번호 (비우면 `data-label` 표시) | `"07"` |
| `data-label` | 번호 없는 장의 라벨 | `"AGENDA"` |
| `data-mod` | 좌상단 모듈명, 목차 묶음 | `"2. AI로 AS-IS 작성과 검증"` |
| `data-title` | 목차·노트 제목 | |
| `data-min` | 진행 시간(분) | `"10"` |
| `data-practice="1"` | 우상단 `실습 N분` 칩 | |
| `data-virtual="1"` | 우상단 `교육용 가상 예시` 칩 | |
| `data-steps="1"` | 클릭 공개 장 (`.rv`는 공개 시 표시, `.rv-hide`는 공개 시 숨김) | |
| `data-note` | 발표자 노트(N) | |

**프롬프트 수정** — 해당 장의 `<textarea data-key="...">` 안 글을 고치면 됩니다. 수강생 브라우저에 예전 수정본이 저장돼 있으면 그것이 먼저 보이므로, 원문 변경 후에는 **원래대로**를 눌러 확인하세요.

**저작권 문구·로고** — `app.js` 상단 `/* ---------- chrome ---------- */` 부분에서 모든 장에 일괄 적용됩니다.

**장 추가** — 기존 `<section>`을 복사해 붙이고 data 속성만 바꾸면 이동·목차·노트에 자동 반영됩니다. 차트가 필요하면 `app.js`의 `onEnter()`에 생성 함수를 연결하세요.
